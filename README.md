# AstrBot Plugin StreamChunk 智能流式消息分段插件

面向不支持原生流式消息的平台（如 QQ 等）的中间件插件。  
插件在本地接管流式输出，根据 `[SHORT]` / `[LONG]` 标签或回退策略决定“分段发送”或“整段发送”。

## 特性
- 智能策略：可注入提示词，引导模型在回复开头输出 `[SHORT]` 或 `[LONG]`；规则会追加到本轮用户输入末尾，随后随请求组装为最后一条用户消息，提示词按回复类型而非字数判定，默认 `[SHORT]`：聊天式回复（即使分多段）使用 `[SHORT]`，只有代码、列表、表格、步骤教程、文章或详细讲解等需要整体阅读的内容使用 `[LONG]`。
- 本地流式：保留模型流式生成，在 AstrBot 本地消费并发送。
- 可配置分段：可自定义分段标点、最小/最大分段长度、发送间隔等。

## 适用场景
建议在不支持 Streaming 的 IM 平台启用；支持原生流式的平台通常无需开启（可通过配置控制）。

提示词注入优先使用 AstrBot 4.25 起提供的临时内容块；4.25 之前的版本会自动改用系统提示词注入，功能可用但模型对规则的注意力弱于前者。

## 配置项
以下配置均可在前端管理面板调整：

1. `enabled`：启用/禁用插件。
2. `only_unsupported_platform`：仅在不支持原生流式的平台生效。
3. `local_stream_processing`：本地接管并消费流式输出。
4. `only_model_result`：仅处理模型结果，忽略普通插件等非模型结果。
5. `inject_prompt`：向本轮用户输入追加标签规则；版本不支持临时内容块时改用系统提示词注入。
6. `default_mode_no_tag`：模型未输出标签时的回退模式，可选 `short` / `long` / `auto`。
7. `auto_short_max_chars`：`auto` 模式的短消息字数阈值。
8. `split_punctuations`：短消息分段触发正则，支持跨字符匹配（例如 `\r\n`、`\.{3}`）。
9. `drop_punctuations`：分段后末尾命中该正则时丢弃匹配内容，支持多字符匹配（例如 `\.{3}`）。
10. `min_chunk_chars`：最小分段片段长度。达到该长度后，遇到分段标点才会切分。
11. `max_chunk_chars`：最大分段片段长度。达到后强制切分。
12. `max_short_chunks`：SHORT 模式最多分段数。超过后，剩余内容改为一次发送；`0` 表示不限制。
13. `segment_interval_seconds`：分段消息之间的发送延迟（秒）。

## 说明
- 标签优先在回复开头识别；开头没有标签时，也会识别并移除回复末尾的 `[SHORT]` / `[LONG]`（包括 `\[SHORT]` 这类转义写法）。正文中间出现的标签不处理，避免误判。
- 流式输出只能在结束时确认末尾标签：若此前尚未按回退模式分段发送，剩余内容按末尾标签发送；否则仅移除标签。
- `[SHORT]` / `[LONG]` 仅作为本轮分段控制信息。每次请求前会清理已有助手历史开头和末尾的标签，包括旧版本遗留的标签，无需新建会话；关闭 `inject_prompt` 也不影响清理。
- 启用 `inject_prompt` 时，标签规则会追加到本轮用户输入，随后随请求组装为最后一个用户消息；历史工具消息、助手工具调用和其他历史内容不会被追加。规则块标记为仅本轮请求可见，不会写入会话历史。AstrBot 4.25 之前的版本缺少临时内容块能力，规则只写入系统提示词。重复触发请求钩子不会重复追加规则。
- 写入 AstrBot 会话历史时会清理全部助手消息（包括工具调用前的文本），启用的群消息历史也会在保存前移除标签；用户消息、工具结果、正文中的标签和非文本内容保持不变。
- 模型响应中的分段模式会单独保存在当前事件中，标签清理不会重排图文组件，也不会恢复旧响应覆盖其他 `on_llm_response` 插件的改写；非流式发送以及响应钩子后转为流式片段的模型回退结果沿用已记录的模式，其他插件在结果中提供的新开头标签优先。
- 清理标签时会移除被耗尽的文本块，避免向模型发送空文本块；若助手消息仅包含标签且没有工具调用或其他内容，则会移除该空消息。
- 在流式和非流式路径中，短消息分段规则保持一致；流式输出遇到图片等非文本组件时，会先发送前面的文本，且这些分段也计入 `max_short_chunks`。
- 无标签的流式前缀一旦不可能补全为控制标签或 `<think>`，立即采用回退策略；只有仍有可能补全时才等待后续片段。`long` 和 `auto` 仍按各自规则缓冲正文。
- 回复开头的完整 `<think>...</think>` 不发送；如果流结束或非流式回复中该思考块仍未闭合，则不发送这部分内容。移除标签或思考块后为空的回复也不发送。
- 当 SHORT 模式分段数量达到 `max_short_chunks` 时，剩余内容会改为一次发送，并继续复用长文本与合并转发逻辑。
- 强制切分会避免拆开常见组合字符、Emoji 修饰符、ZWJ 表情和国旗序列；单个字素过长时，实际长度可能略超过 `max_chunk_chars`。
- 流式输出末尾的单个 `…` 或 `—` 会等待下一片段确认，避免把连续的 `……` 或 `——` 截断。
